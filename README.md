# Юридический ассистент ПСБ — Hack&Change 2026

ИИ-ассистент для юристов банка: отвечает на вопросы по базе нормативных документов (RAG),
ссылается на конкретные положения и обоснованно отказывается, если данных недостаточно.

> **Статус: черновой вариант.** Бэкенд (Go) и фронтенд (React) — рабочий каркас для команды:
> основной сценарий проходит, но поиск пока лексический, а с реальной моделью и базой знаний
> организаторов решение ещё не прогонялось. См. «Роадмап» и «Известные ограничения».

## Запуск одной командой

```bash
cp .env.example .env   # впишите LLM_BASE_URL и LLM_API_KEY
docker compose up --build
```

Интерфейс: http://localhost:8000 (порт хоста — `PORT` в `.env`).
Документы базы знаний кладутся в `data/kb/` (txt, md, docx; подпапки допускаются).

## Архитектура

```
 Браузер (React + TS, Vite)          frontend/
   чат · кликабельные ссылки [n] · панель положений · просмотр документа с подсветкой
        │  POST /api/chat, GET /api/documents/{name}
        ▼
 Go-сервис (net/http, без внешних зависимостей)   backend/
   internal/api        HTTP API + раздача собранного фронтенда
   internal/assistant  контекст: паспорта документов + документы компании целиком [1..K]
                       + хронология изменений законов + найденные фрагменты законов [K+1..]
                       → промпт с правилами достоверности → (самопроверка) → только процитированные источники
   internal/kb         загрузка, документы компании / законы, вырезание инъекций, нарезка,
                       паспорта и хронология, гибридный поиск BM25 + эмбеддинги → реранкер
   internal/llm        /chat/completions, /embeddings, /rerank
        │
        ▼
 API организаторов: DeepSeek V4.1 Flash, bge-m3, реранкер

 submission/   Python-версия для автоматической проверки на платформе (solution.py)
```

Почему Python в `submission/`: платформа хакатона запускает ZIP со скриптом `solution.py`.
`submission/solution.py` и Go-сервис реализуют одну логику (документы компании целиком, паспорта и хронология,
гибридный поиск, защита от инъекций, диалоги, самопроверка); Go-версия дополнительно нумерует фрагменты [n] для интерфейса.
Подробности — [submission/README.md](submission/README.md).

Данные кейса: `data/kb/` — база знаний организаторов, `data/demo/` — демо-вопросы и эталонные ответы,
`data/eval/` — наш расширенный набор из 480 вопросов (dev/test) по всем ситуациям кейса ([описание](data/eval/README.md)).

## API

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/health` | статус и размер базы |
| `POST` | `/api/chat` | `{"question": "...", "history": [{"role": "user", "content": "..."}]}` → `{"answer", "sources", "refused"}` |
| `GET` | `/api/documents` | список документов |
| `GET` | `/api/documents/{name}` | полный текст документа |

## Переменные окружения

Полный список — в [backend/README.md](backend/README.md#настройки-env). Главное:

| Переменная | Описание | По умолчанию |
|---|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY` | OpenAI-совместимый API (не коммитить ключ!) | — |
| `LLM_MODEL` | модель генерации | `deepseek/deepseek-v4.1-flash` |
| `EMB_MODEL`, `RERANKER_MODEL` | эмбеддинги и реранкер | `baai/bge-m3`, `cohere/rerank-5-fast` |
| `USE_EMBEDDINGS` | `0` — только BM25 | `1` |
| `LAW_TOP_N` | фрагментов законов в промпт | `8` |
| `SELF_CHECK` | самопроверка ответа вторым вызовом | `0` |
| `PORT` | порт на хосте | `8000` |

## Разработка без Docker

Нужны Go 1.23+ и Node.js 20+.

```bash
# бэкенд (из корня репозитория)
cd backend && KB_DIR=../data/kb STATIC_DIR=../frontend/dist go run ./cmd/server
```

```bash
# фронтенд с hot reload — http://localhost:5173, /api проксируется на :8000
cd frontend && npm install && npm run dev
```

```bash
# тесты
cd backend && go test ./...
```

## Сабмит на автоматическую оценку

```bash
pip install httpx==0.28.1 pytest
python -m pytest submission                       # офлайн-тесты
export LLM_BASE_URL=... LLM_API_KEY=...           # ключ только в окружении
python submission/evaluate.py                     # прогон демо-вопросов + оценка по эталону
./submission/make_submission.sh                   # → submission/submission.zip для платформы
```

## Порядок проверки основного сценария

1. Положить документы в `data/kb/`, заполнить `.env`, выполнить `docker compose up --build`.
2. Открыть http://localhost:8000, задать вопрос по базе — в ответе ссылки `[n]`; клик по ссылке подсвечивает положение справа, «Открыть документ» показывает его в полном тексте.
3. Задать вопрос вне базы — ассистент сообщает, что данных недостаточно (жёлтая плашка).
