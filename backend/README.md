# Бэкенд: как он устроен

Go 1.23, только стандартная библиотека. Один бинарник: держит базу знаний в памяти, отвечает на API
и раздаёт собранный фронтенд. Логика повторяет `submission/solution.py` (то, что оценивает платформа),
но с нумерацией фрагментов [n] — чтобы интерфейс подсвечивал источники.
**Меняете промпт, нарезку или поиск — правьте обе версии.**

## Структура

```
backend/
├── cmd/server/main.go           конфиг → база → поиск/эмбеддинги → ассистент → HTTP
└── internal/
    ├── config/config.go         настройки из env (имена как у платформы: LLM_BASE_URL, LLM_API_KEY, EMB_MODEL…)
    ├── kb/kb.go                 загрузка, классификация (документы компании / законы), вырезание инъекций, нарезка, BM25
    ├── kb/passport.go           паспорта документов компании и хронология изменений законов
    ├── kb/retriever.go          гибридный поиск: BM25 + эмбеддинги (RRF) → реранкер; при сбое API — только BM25
    ├── llm/client.go            /chat/completions (до 5 попыток, 4xx не повторяются), /embeddings, /rerank
    ├── assistant/assistant.go   сборка контекста, системный промпт, самопроверка, отбор процитированных источников
    └── api/api.go               роуты, JSON, раздача frontend/dist
```

## Что происходит при старте

1. Читает `KB_DIR` (txt, md, docx). Файл `законы__*` или с `ФЗ_/НК_/ТК_/КоАП_` в имени — закон, остальное — документ компании.
   Название закона — из строки «Источник:», строки `URL:` / `Дата выгрузки:` удаляются.
   Строки, адресованные ИИ («для ИИ-ассистента», «игнорируй…»), вырезаются как инъекции.
2. Режет: документы компании — по разделам верхнего уровня («1. Предмет договора», шапка отдельно);
   законы — по абзацам до 1400 символов, не разрывая абзац.
3. Строит паспорта документов компании и хронологию изменений законов (с 2020 г.).
4. Если задан `LLM_BASE_URL` и `USE_EMBEDDINGS=1` — считает эмбеддинги фрагментов законов (bge-m3).
   Нет API — работает только BM25.

## Путь запроса `POST /api/chat`

```
{"question": "...", "history": [{"role":"user|assistant","content":"..."}]}
  1. поиск по вопросу (вес 1) и по вопросу с 2 предыдущими репликами (вес 0,5); аббревиатуры и бытовые слова
     («штраф», «перерабатывать») расширяются юридическими терминами; явная ссылка «ст. 164 НК» / «152-ФЗ» —
     статья обязательно в контексте; короткая статья (до 8000 симв.) — всеми фрагментами, т. е. целиком
  2. контекст «БАЗА ЗНАНИЙ»:
       паспорта документов компании
       [1..K]   все разделы документов компании (если их больше COMPANY_FULL_LIMIT символов — 12 найденных)
       перечень законов базы
       хронология изменений найденных законов
       [K+1..]  LAW_TOP_N найденных фрагментов законов
  3. system (8 правил: ссылки [n] + пункт, честный отказ, ошибка в вопросе, редакции на дату,
     похожие контрагенты, законность, защита роли, не по теме) + история (только user/assistant) + контекст и вопрос
  4. номер документа в ответе, которого нет ни в базе, ни в вопросе → одна просьба модели исправить ответ;
     SELF_CHECK=1 — второй вызов модели сверяет любой ответ с базой и исправляет
  5. sources = фрагменты, чьи номера [n] есть в ответе; refused = ответ без единой ссылки
→ 200 {"answer", "sources": [{n, id, doc, docTitle, title, text, score}], "refused"}
→ 502 {"error"} — модель недоступна
```

## API

| Метод | Путь | Ответ |
|---|---|---|
| `GET` | `/api/health` | число документов, законов, фрагментов |
| `POST` | `/api/chat` | см. выше |
| `GET` | `/api/documents` | `[{name, kind, title}]` |
| `GET` | `/api/documents/{name...}` | `{name, title, kind, text}` — очищенный текст документа |

## Настройки (env)

| Переменная | По умолчанию | |
|---|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY` | — | OpenAI-совместимый API (на платформе — API организаторов) |
| `LLM_MODEL` | `deepseek/deepseek-v4.1-flash` | генерация |
| `EMB_MODEL`, `EMBEDDER_API_KEY` | `baai/bge-m3`, ключ LLM | эмбеддинги |
| `RERANKER_MODEL`, `RERANKER_API_KEY` | `qwen/qwen3-reranker-8b`, ключ LLM | Qwen3 Reranker 8B; при отказе API перебираются варианты имени |
| `USE_EMBEDDINGS` | `1` | `0` — только BM25 |
| `LAW_TOP_N` / `LAW_CANDIDATES` | 8 / 30 | фрагментов законов в промпт / в реранкер |
| `COMPANY_FULL_LIMIT` | 60000 | порог «документы компании целиком» |
| `SELF_CHECK` | `0` | самопроверка ответа |
| `LLM_TEMPERATURE`, `MAX_TOKENS`, `LLM_TIMEOUT_SEC` | 0, 1500, 120 | |
| `TODAY` | системная дата | дата «сегодня» в формате ДД.ММ.ГГГГ (для паспортов и промпта) |
| `ADDR`, `KB_DIR`, `STATIC_DIR` | `:8000`, `data/kb`, `frontend/dist` | |

## Запуск и тесты

```bash
cd backend
KB_DIR=../data/kb STATIC_DIR=../frontend/dist LLM_BASE_URL=... LLM_API_KEY=... go run ./cmd/server
go test ./... && go vet ./...
```

Тесты: классификация и вырезание инъекций, нарезка, поиск с аббревиатурами, паспорта и хронология
(на вымышленных документах — проверка, что извлечение не подогнано под базу кейса), состав контекста,
отбор процитированных источников, отбрасывание поддельных system-сообщений.
