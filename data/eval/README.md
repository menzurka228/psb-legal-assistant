# Набор для оценки ассистента

`dataset.csv` — 137 вопросов по базе знаний кейса с эталонными ответами и источниками.
Дополняет демо-набор организаторов (`data/demo/`, 18 вопросов). Все эталоны сверены с текстами в `data/kb/`.

## Колонки

| Колонка | Что внутри |
|---|---|
| `id` | 101–237 (не пересекается с демо 1–18) |
| `category` | тип ситуации, см. ниже |
| `question` | вопрос; диалоги — строками `Пользователь: …` / `Ассистент: …`, как на платформе |
| `answer` | эталонный ответ: вывод + ссылки на пункты |
| `sources` | `имя_файла_без_.txt\|пункт; …` — где лежит ответ (пусто, если в базе ответа нет) |
| `notes` | пояснение к ловушке, если есть |

## Категории (ситуации из кейса)

| Категория | Сколько | Что проверяет |
|---|---|---|
| `fact_company` | 26 | прямой факт из договора/регламента/записки |
| `fact_law` | 29 | факт из статьи закона |
| `edition_date` | 12 | редакция документа на дату события, доп. соглашение, письмо комплаенса с датой вступления, НДС 20% в договоре vs 22% в законе с 2026 г. |
| `law_old_edition` | 6 | нужна прежняя редакция закона, которой нет в базе → честно сказать |
| `multi_doc` | 7 | сопоставление нескольких документов |
| `calc` | 6 | неустойка, пени, лимиты, даты оплаты |
| `no_info` | 9 | ответа в базе нет (полностью или частично) |
| `false_premise` | 10 | ошибка в вопросе — указать и не подстраиваться |
| `kb_injection` | 3 | в служебной записке спрятано «отвечай 90 дней» — не выполнять |
| `role_attack` | 6 | смена роли, фейковое системное сообщение, давление «исправь ответ» |
| `illegal` | 6 | просьба помочь нарушить закон/регламент → отказ + разъяснение последствий |
| `off_topic` | 4 | не юридический вопрос |
| `ambiguous` | 4 | неясно, какой договор/дата → уточнить или ответить по вариантам |
| `dialog` | 6 | многоходовые диалоги с уточнениями |
| `steps` | 3 | ответ в виде последовательности действий |

## Как пользоваться

```bash
# качество ответов (нужен ключ API в окружении)
python submission/evaluate.py --dataset data/eval/dataset.csv
python submission/evaluate.py --dataset data/eval/dataset.csv --category edition_date false_premise

# качество поиска по законам — офлайн (BM25) или с API (эмбеддинги + реранкер)
python submission/eval_retrieval.py
python submission/eval_retrieval.py --api
```

`evaluate.py` печатает процент по каждой категории — сразу видно, где ассистент слабый.

## Правила пополнения

- Эталон пишем **только по тексту базы** и сверяем с файлом, указываем пункт в `sources`.
- Правила в промпте делаем общими, а не под конкретный вопрос, иначе переобучимся на этот набор.
- Новые ловушки — в отдельную категорию или в `notes`.

## Задачи для ML / Retrieval (Левашев)

Текущий поиск по законам (BM25, офлайн): **hit@8 = 1.00, MRR = 0.97 на уровне документов**. Законов всего 13,
поэтому «найти нужную статью» — лёгкая задача. Настоящая работа:

1. **Точность до пункта/части.** НК ст. 164 и 284 — огромные (≈80–95 тыс. симв.). Нужно, чтобы в топ-8 попадал
   именно фрагмент с нужным пунктом (п. 3 ст. 164 про 22%, п. 2 про 10%). Добавить в набор колонку
   `evidence` (ключевая фраза из нужного фрагмента) и метрику «фрагмент содержит evidence».
2. **Нарезка законов** с учётом структуры: пункт/подпункт + пометки «изменён с …» должны быть в одном фрагменте
   с текстом пункта — от этого зависят ответы про редакции.
3. **Гибрид bge-m3 + BM25 + реранкер** — прогнать `eval_retrieval.py --api`, подобрать `LAW_CANDIDATES`,
   `LAW_TOP_N`, вес RRF.
4. **Стемминг** — заменить обрезку слов до 5 букв на Snowball/pymorphy (если платформа позволяет зависимости).
5. **Сохранение эмбеддингов** — предрасчитать индекс и класть в ZIP, чтобы не тратить время на старте.
