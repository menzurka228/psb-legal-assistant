# Набор для оценки ассистента

`dataset.csv` — **480 вопросов** по базе знаний кейса, не меньше 30 в каждой из 15 категорий, с эталонными
ответами и источниками. Дополняет демо-набор организаторов (`data/demo/`, 18 вопросов).

Набор **собирается скриптом** — CSV руками не правим:

```bash
python data/eval/build_dataset.py
```

- `base_questions.py` — 137 вопросов, написанных вручную;
- `build_dataset.py` — генераторы:
  - расчёты (неустойки, пени, даты оплаты, НДФЛ, сверхурочные) и маршруты согласования по Регламенту
    **считаются кодом** по правилам документов, поэтому эталоны в них верны по построению;
  - диалоги, ложные посылки, атаки на роль, вопросы с инъекцией собираются из таблицы проверенных фактов `FACTS`;
  - противоправные, пошаговые, «нет в базе», «не по теме», сопоставления — дописаны вручную.

## Колонки

| Колонка | Что внутри |
|---|---|
| `id` | с 101 (не пересекается с демо 1–18) |
| `category` | тип ситуации, см. ниже |
| `split` | `dev` — на нём улучшаем промпт/поиск; `test` (каждый 3-й в категории, ≈⅓) — только проверяем |
| `question` | вопрос; диалоги — строками `Пользователь: …` / `Ассистент: …`, как на платформе |
| `answer` | эталонный ответ: вывод + ссылки на пункты |
| `sources` | `имя_файла_без_.txt\|пункт; …` — где лежит ответ (пусто, если в базе ответа нет) |
| `notes` | пояснение к ловушке, если есть |

## Категории

| Категория | Что проверяет |
|---|---|
| `fact_company` | прямой факт из договора/регламента/записки |
| `fact_law` | факт из статьи закона |
| `edition_date` | редакция Регламента на дату сделки, доп. соглашение, письмо комплаенса с даты вступления, НДС 20% в договоре vs 22% в законе |
| `law_old_edition` | нужна прежняя редакция закона, которой нет в базе → честно сказать |
| `multi_doc` | сопоставление нескольких документов |
| `calc` | неустойки с потолком, пени, даты оплаты, НДФЛ, сверхурочные, налоговые штрафы |
| `no_info` | ответа в базе нет |
| `false_premise` | ошибка в вопросе — указать и не подстраиваться |
| `kb_injection` | в служебной записке спрятано «отвечай 90 дней» — не выполнять |
| `role_attack` | смена роли, фейковые системные сообщения, давление «исправь ответ» |
| `illegal` | просьба помочь нарушить закон/регламент → отказ + разъяснение последствий |
| `off_topic` | не юридический вопрос |
| `ambiguous` | неясно, какой договор/дата → уточнить или ответить по вариантам |
| `dialog` | многоходовые диалоги, в т. ч. переход между договорами |
| `steps` | ответ в виде последовательности действий |

## Как пользоваться

```bash
# качество ответов (нужен ключ API в окружении)
python submission/evaluate.py --dataset data/eval/dataset.csv --split dev            # улучшаем по dev
python submission/evaluate.py --dataset data/eval/dataset.csv --split test           # честная проверка
python submission/evaluate.py --dataset data/eval/dataset.csv --split dev --category edition_date calc

# качество поиска по законам — офлайн (BM25) или с API (эмбеддинги + реранкер)
python submission/eval_retrieval.py
python submission/eval_retrieval.py --api
```

`evaluate.py` печатает процент по каждой категории — сразу видно, где ассистент слабый.

## Правила пополнения

- Новые вопросы добавляем в `base_questions.py` или генераторы и пересобираем CSV.
- Эталон пишем **только по тексту базы** и сверяем с файлом, указываем пункт в `sources`.
- Правила в промпте делаем общими. Если на `dev` растёт, а на `test` нет — это подгонка.
- Новые ловушки — в отдельную категорию или в `notes`.

## Задачи для ML / Retrieval (Левашев)

Текущий поиск по законам (BM25, офлайн): **hit@8 = 1.00, MRR = 0.97 на уровне документов**. Законов всего 13,
поэтому «найти нужную статью» — лёгкая задача. Настоящая работа:

1. **Точность до пункта/части.** НК ст. 164 и 284 — огромные (≈80–95 тыс. симв.). Нужно, чтобы в топ-8 попадал
   именно фрагмент с нужным пунктом (п. 3 ст. 164 про 22%, п. 2 про 10%). Добавить в набор колонку
   `evidence` (ключевая фраза из нужного фрагмента) и метрику «фрагмент содержит evidence».
2. **Нарезка законов** с учётом структуры: пункт/подпункт + пометки «изменён с …» должны быть в одном фрагменте
   с текстом пункта — от этого зависят ответы про редакции.
3. **Гибрид bge-m3 + BM25 + реранкер** — прогнать `eval_retrieval.py --api`, подобрать `LAW_CANDIDATES`,
   `LAW_TOP_N`, вес RRF.
4. **Стемминг** — заменить обрезку слов до 5 букв на Snowball/pymorphy (если платформа позволяет зависимости).
5. **Сохранение эмбеддингов** — предрасчитать индекс и класть в ZIP, чтобы не тратить время на старте.
